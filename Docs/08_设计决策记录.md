# 08 设计决策记录（ADR）

> 记录启动期的关键技术决策与理由。变更决策时在此追加条目，不删除历史。
> **当前以 ADR-012 为准**：它覆盖旧条目中输入重绑/录音回看降级、打断落标记、脚手架无损重建等结论。ADR-002/008/009/010/011 的原文含历史状态，不能直接作为当前任务依据。

## ADR-001 引擎与渲染管线：内置渲染管线 2D 模板

**决策**：使用团结引擎 1.10.4 的内置渲染管线 2D 模板（`cn.tuanjie.template.2d`），不采用 URP 2D。
**理由**：策划 10.1 明确"优先使用所选团结版本已验证可运行的 2D 模板；不为视觉效果临时迁移整套渲染管线"；本作不需要 URP 专有能力（Shader Graph、后期），Sprite Mask 方案在内置管线验证成本最低。
**影响**：如后期需要世界坐标裁切 Shader（策划 11.1 增强项），届时再评估迁移。

## ADR-002 输入方案：旧 Input Manager + IInputSource 抽象

**决策**：首版用旧 `Input` API 实现 `InputRouter`，经 `IInputSource` 接口暴露给玩法。
**理由**：模板未包含 Input System 包（策划 10.1：不指定未经验证的版本号）；抽象层保证未来切换 Input System 只改 `Player` 模块一处。键位集中在 `InputBindings`（可 Inspector 配置），运行时重绑 UI 属后续增强（P2）。

## ADR-003 模块化：每个 Scripts 子目录一个 asmdef，星形依赖

**决策**：9 个游戏程序集 + EditorTools + Tests；模块间禁止横向引用具体类，跨模块协作只经 `Core/Interfaces`；装配层向下依赖（Level→TimeBoundary、Audio→TimeBoundary、UI→TimeBoundary）显式声明。
**理由**：策划 10.2 模块目录是团队分工边界（策划 13.2）；asmdef 强制依赖方向、缩短增量编译、并行开发时把冲突挡在编译期。依赖倒置让安全校验（TimeBoundary）无需依赖玩家实现（Player），测试也能用替身（`PlayerMock`）。
**已付代价**：Core 中接口较多；换来的是模块可独立演进。

## ADR-004 服务装配：ServiceRegistry 显式注册，不做全场景查找

**决策**：各服务在 `Awake/OnBootInitialize` 向静态 `ServiceRegistry` 注册接口实例；Bootstrap 按 `InitializeOrder` 全场景一次性初始化。
**理由**：策划 10.3 要求"全局管理对象与关卡对象通过显式引用或注册获取，不在每帧全场景查找；重开关卡不重复创建音频、输入和事件监听器"。系统根只存在于 Bootstrap 场景并 `DontDestroyOnLoad`。

## ADR-005 时间切换渲染：Sprite Mask（背景）+ 整体切换（机关）

**决策**：背景双年代 Sprite 用两个 SpriteMask 矩形裁切显示；关键 `TemporalObject` 的渲染与碰撞随锚点**整体**启停，不做逐像素切断。
**理由**：策划 11.1/4.4：Sprite Mask 只解决显示；实际通行物必须整体出现或消失，避免"可见一半却有整块碰撞"。0.15s 透明度淡入遮掩切换（策划 11.2），轮廓闪光为后续增强。

## ADR-006 边界提交：逐阈值安全校验

**决策**：拖动目标先经 `BoundaryChangePlan` 收集跨过的阈值（按方向排序、同阈值成组），逐组调用 `TemporalSafetyResolver`（覆盖检测 + 支撑撤除检测），任一组不安全即停在 `SafeBoundaryBefore` 并提示。
**理由**：策划 11.4 明确要求"必须检查中间阈值，不能只检查拖动终点"；安全检查用预配置包围盒的几何相交（策划 11.4：不依赖临时启用真实障碍把角色推出去）。滞回（0.05）防止停在锚点上抖动（策划 4.4）。

## ADR-007 存档：JSON + 临时文件替换 + 单备份

**决策**：`JsonUtility` 序列化 `SaveData`；写入路径 tmp → 校验 → 旧文件转 backup → 覆盖正式文件；损坏时回落 backup（`UsedBackup`），双损时报告 `Corrupted` 交 UI 决策。
**理由**：策划 12.3。设置（音量/字幕）单独文件，重开游戏不重置偏好。恢复顺序严格执行 12.2（先环境后放人）。saveVersion + `Migrate` 预留升级。

## ADR-008 剧情数据：ScriptableObject 集中维护 + 标记幂等

**决策**：全部对白为 `DialogueEntry` 资产（`DialogueLibrary` 汇总）；一次性判定用 `setFlags` 是否已全部写入；优先级打断时立即落标记。
**理由**：策划 10.5（禁止脚本硬编码剧情文本）、12.1（关键标记只在演出完成或合法跳过后写入）、5.5（跳过配音仍写标记）。

## ADR-009 场景生成：EditorTools 一键脚手架

**决策**：`ProjectScaffolder` 一键配置层/排序层/Build 列表并生成 8 个场景骨架 + 12 个数据资产（初值取策划第 7 章灰盒坐标）；可从菜单或 `-batchmode -executeMethod` 运行，幂等可重跑。
**理由**：保证团队任何成员拉取仓库后都有可运行的起点；策划第 7 章坐标直接进入 `LevelDefinition`，避免手工录入错误。骨架中的 UI 面板文本/按钮留空由美术接入（代码对空引用容错）。

## ADR-010 测试边界：核心逻辑纯函数化 + 少量 EditMode 测试

**决策**：阈值排序/安全判定/存档往返/标记幂等/状态机共 23 个 EditMode 测试；关卡可读性、情绪、手感靠试玩（策划 15.5：不用大量镜像实现的测试替代人工验证）。
**理由**：策划 15.5 明确建议的测试面；安全检测刻意写成不依赖物理帧时序的静态几何判定，使可测性成为架构属性。

## ADR-012 总规划一致性校正（2026-10-17，覆盖以下旧结论）

本条优先于 ADR-002/008/009/011 中相冲突的表述；上文保留为历史记录，不代表当前交付范围。

- **输入与 UI**：总规划 5.1/5.2 要求关键输入重绑、Tab 目标/录音回看；列入首版交付，不再按 P2/P1 裁掉。确认框先有可用文字与确认/取消，再做视觉。候选轮廓是 5.3 的交互反馈要求，可用普通 Sprite 实现，不依赖复杂 Shader。
- **剧情标记**：撤销“优先级打断立即落标记”的设计。系统抢占、拒播和取消均不代表已看或合法跳过；关键演出完成或玩家合法跳过才落完成标记。当前实现差距见 02。
- **生成器**：重复生成并不等于保留手工编辑。脚手架会覆盖场景和数据；不得作为只读校验，正式内容重建前在隔离副本比较差异。资产数、UI 引用和测试数以当前仓库/11 的有日期证据为准，不沿用 ADR-009/010 的初始数量。
- **阶段与范围**：阶段 A 先验证 L02，尽早 Windows 构建，再验收 L01B 样板与全流程；可并行准备资源，但不据两周建议承诺工期。完整配音为 P1，关键手部/照片/病房揭示信息为 P0，可先用占位插画承载。
- **安全实现**：包围盒近似、目标有碰撞、局部滞回不能分别替代精确路线验证、脚下支撑确认和完整拖动滞回验收；统一物理步骤提交为总规划 11.3 要求。
