# 04 场景搭建指南

> 描述项目中**必须遵守**的场景结构约定。脚手架生成场景可供结构参照，仍须逐项验收；生成操作会写入场景和数据，不是只读校验。

## 1. 排序层与物理层（已由脚手架配置）

### 1.1 排序层（策划 8.5，从后到前）

| 排序层 | 用途 |
| --- | --- |
| `Sky` | 远景天空 |
| `FarBuildings` | 远景建筑 |
| `EraBackground` | 双年代背景（受 Sprite Mask 控制） |
| `ConstantStructure` | 恒定结构（砖台、门槛、主梁） |
| `EraPlatform` | 年代平台 / 年代物体 |
| `Characters` | 角色（主角、阿黄） |
| `Foreground` | 前景装饰 |
| `BoundaryFx` | 边界特效（边界线等） |

规则：可通行平台不得被前景遮住；字幕区域避免覆盖必看机关；机关和角色不得使用不同视差系数。

### 1.2 物理层（User Layer 8–13）

| 层 | 用途 |

## 2. Bootstrap 场景（系统根，策划 10.3）

```
SystemRoot                          ← DontDestroyOnLoad（Bootstrap 组件保证）
├─ Bootstrap / GameSession
├─ SaveService / CheckpointService
├─ AudioService / SfxLibrary
├─ NarrativeDirector / DialogueLibrary / DialoguePlayer
├─ InputRouter
└─ UICanvas（Canvas，Screen Space Overlay，参考分辨率 1920×1080）
   ├─ HudService
   ├─ SubtitlePanel / ObjectivePanel / InteractionPrompt
   ├─ BoundaryHandle（顶部把手，命中区 ≥44px）
   ├─ HintToast / EraBadge / FadeScreen
   ├─ PauseMenu / ResumeConfirmDialog
EventSystem
```

- 关卡场景**不**放置任何系统组件；重开关卡不会重复创建音频、输入与事件监听器。
- 灰盒目前使用 `UnityEngine.UI.Text` 与按钮；迁移 TMP 时须同步组件类型和引用。空引用容错不代表字幕或确认框可用。
- `GameSession.levelCatalog` 在此场景按通关顺序拖入全部 `LevelDefinition`。

## 3. 关卡场景结构（每关一个 .scene；L01 为双房间）

```
RoomRoot_<roomId>                   ← LevelRoot + TemporalObjectRegistry
│                                     + BoundaryController + LevelDirector + HintDirector
├─ TemporalVisual
│  ├─ PastMask                      ← SpriteMask，矩形遮罩
│  ├─ PresentMask                   ← SpriteMask，独立排序范围
│  └─ 双年代背景 Sprite             ← VisibleInsideMask，分别匹配遮罩范围
└─ Content
   ├─ Ground（layer Ground，BoxCollider2D，站稳表面配置摩擦）
   ├─ Spawn_<id>（SpawnPoint）
   ├─ Checkpoint_mid（Trigger + CheckpointMarker）
   ├─ KillZone（Trigger + KillZone）
   ├─ Temporal_<objectId>           ← TemporalObject
   │  ├─ Past（SpriteRenderer + 对应年代 Collider2D）
   │  └─ Present（SpriteRenderer + 对应年代 Collider2D）
   └─ Exit_NextLevel（layer Interactable + ExitDoor）
Main Camera                        ← 场景相机；CameraRig2D 使用活动房间范围
```

要点：

1. **房间范围**：`LevelRoot` 的 `boundaryMin/Max` 决定边界把手可拖范围；`cameraBounds`（Rect）决定镜头边界。
2. **双年代背景**：`TemporalVisualController` 持有 `PastMask/PresentMask` 引用与 `roomLeft/roomRight`；背景 Sprite 全部设 `Mask Interaction = Visible Inside Mask` 并放 `EraBackground` 层。恒定层不受遮罩。
3. **出生点命名**：`Spawn_<spawnId>` 与 `LevelDefinition.spawnId` 一致；**检查点 marker 的 `checkpointId` 若与某出生点同名，恢复优先放该出生点**（策划 12.2：优先存安全出生点 ID）。
4. **站稳平台摩擦**：玩家站定依赖地面摩擦，树枝缓坡/砖台请挂 `PhysicsMaterial2D`（friction > 0）。
5. **梯子**：`LadderZone` 的 isTrigger 罩住梯子全程；梯顶与平台重叠一小段，方便爬出。
6. **防绕关**（策划 16 风险二）：隔断缺口 > 最大跳距（理论水平 ≈2.25 单位）；储物柜等"不可推、不可跳上"的隔断物画到顶，不给可站顶部。

## 5. 运动包络（策划 6.2，关卡设计红线）

- 移动 3.5 u/s；跳 5.8 u/s；等效重力 18 u/s²。
- 理论跳高 ≈0.93 u；同高度水平 ≈2.25 u。
- **必经**水平跳跃 ≤1.2 u；**必经**向上跳 ≤0.6 u；高处移动靠梯子/树枝坡面。
- 房间宽建议 24—32 u；角色 1.5—1.7 u 高。

## 6. 制作规格（策划 8.6）

- 设计基准 1920×1080；其他宽高比保留关卡完整范围并补边。
- 全项目统一 PPU=100。
- 双年代 Sprite **相同原点与参考坐标**。
- 关键平台边缘与树枝通行面有稳定浅色边缘，不依赖霓虹描边。
- 对白字库覆盖全部中文标点、数字与姓名；发布前验证不缺字。

## 7. 各房间验收与坐标换算

上述锚点为总规划局部示意，不能与场景世界坐标混用。当前 L01A 范围为 0–20，初始 B=0；L01B 在同场景使用世界范围 40–69，初始 B=69。当前 L01B 木阶梯/树锚点为世界 x=48/58，对应局部 x=8/18（偏移 +40）；迁移布局时同步换算边界、出生点、相机和锚点。每房间单独保存 B，跨房间重显年份角标。当前 L02 旧梯 Definition 为 x=13，而总规划示意为 x=17；坐标允许迭代，但必须验证“先爬梯上恒定砖台，再切换左侧踏台”的顺序不可绕过。下表保留总规划示意坐标，实测按当前资产阈值换算。

以下不等式表示解题方向，实际拖动须留出滞回余量，避免停在阈值上；坐标不是可直接免测的成品布局。

| 房间 | 标准解与出口约束 | 检查点 / 防绕关 |
| --- | --- | --- |
| L00 | B<10 使栅栏出现成年人缺口，E 开内门；开门后保持通行 | 入院后；真实门梁防跳过 |
| L01A | B>12 恢复盖板，过渠；脚下盖板不可撤除 | 对岸石台；渠宽约 4u，下方跌落恢复，无游泳 |
| L01B | 局部 8<B<18，过去阶梯接现在整树枝 | 入口石门槛；阶梯末端到出口缺口大于实测跳距 |
| L02 | 从右侧 x=23 出发，B>17 → 爬旧梯 → 站 x=11 恒定砖台且离开梯子 Trigger → B<6 → 维修踏台 → 左侧出口；必查校服后放行 | 砖台保存安全落点与边界；不能同时获得左侧现在踏台与右侧过去木梯 |
| L03 | 7<B<15 → 过地板/踏板 → 站 x=20 石门槛 → B>24 消去柜子 → 照片揭示 | 门槛及揭示后；门槛到照片须有恒定地面，柜子到顶不可推 |
| L04 | 右侧恒定窗台先 E 看高处 → B<4 使整树成年 → 沿枝条到暗格 → E 告知位置 | 进入窗台及告知完成；暗格高于原地跳跃可交互范围；无第二条路 |

末关要转换的可见旧物锚点位于树干右侧，以布局自然让院落主体进入现在；不增加“全图现在比例达到阈值”门锁。玩家可退回恒定窗台再看过去。出生、恢复和快速拖动均须重验标准解。

双背景遮罩须分别设置互不串扰的排序范围；仅将两组 Sprite 都设为 `Visible Inside Mask` 不足以隔离年代。关键机关、角色、UI 不受背景遮罩。房间的 Content 与视觉层应归属对应房间根或受其激活逻辑统一管理，切房后仅活动房间响应输入。
