## 2. 程序集划分（asmdef）与依赖图

每个 `Scripts/<模块>` 目录一个程序集，强制依赖边界，支持团队并行开发与增量编译：

```
                 ┌──────────── BorrowTomorrow.Core（零依赖） ─────────────┐
                 │  GameSession / GameStateMachine / ServiceRegistry    │
                 │  StoryFlagStore / 全部跨模块接口 / 数据定义(SO)      │
                 └───────────────────────────────────────────────────────┘
      ▲          ▲          ▲          ▲          ▲         ▲          ▲
   Player   TimeBoundary   Level   Narrative    Audio      Save        UI
                                                     │（Audio→TimeBoundary）
      Level → TimeBoundary（房间装配）；UI → TimeBoundary；其余运行时模块只依赖 Core。
      EditorTools（仅编辑器）→ 全部游戏程序集；Tests → Core/TimeBoundary/Save。
```

- **规则**：模块之间不允许横向引用具体类，跨模块协作只通过 `Core/Interfaces` 中的接口（依赖倒置）。
- **例外**（装配层向下依赖，均无环）：`Level → TimeBoundary`（LevelRoot 装配边界控制器）；`Audio → TimeBoundary`（环境声挂年代物体）；`UI → TimeBoundary`（把手调用边界控制器）。

## 4. 核心数据流

```
InputRouter(IInputSource)
   ├─ Update采样 ─→ PlayerMotor2D(FixedUpdate 应用)
   ├─ E ─→ DialoguePlayer.Advance（对白中优先） / PlayerInteractor
   ├─ Q/R、把手 ─→ BoundaryController
   │        └─ BuildPlan(committed→target)          ← TemporalObjectRegistry
   │             每个阈值组: TemporalSafetyResolver.Evaluate ← IPlayerContext
   │             允许 → ApplyEra(整组物理+渲染) → CommitBoundary
   │             阻止 → 停在阈值前 → OnAdjustBlocked → HUD"先到稳固的地方。"
   └─ Esc/Backspace → GameSession(状态机) / ResumeConfirmDialog
渲染·音频·HUD 只读已提交 B（BoundaryController.OnBoundaryCommitted）
```

## 5. 边界提交算法（策划 11.4 的实现对照）

`BoundaryController.ProcessAdjustment` 逐条对应策划步骤：

1. 候选 B 生成：鼠标把手（`RequestAdjustment`，仅拖动中受理，防误触瞬移）或 Q/R 连续步进（`Update` 内）。
2. 阈值收集：`TemporalObjectRegistry.BuildPlan` → `BoundaryChangePlan.Build`，区间 `(from, to]`（右移）/`[to, from)`（左移），按移动方向排序。
3. 同一阈值（±0.001）物体归为一笔变更（`ThresholdStep`）。
4. 安全检查：`TemporalSafetyResolver.Evaluate` —— ①目标状态包围盒与玩家身体包围盒相交（当前为 AABB 近似，并非精确胶囊查询）（`BodyOverlapped`）；②玩家脚下 Collider 属于被切物体且目标状态无碰撞（尚不足以证明目标碰撞仍在脚下）（`SupportRemoved`）。
5. 不安全：`CommitBoundary(step.SafeBoundaryBefore)`，广播 `OnAdjustBlocked` → HUD 显示统一提示。
6. 提交：整组 `ApplyEra`（物理与渲染同步，0.15s 淡入遮掩），`OnBoundaryCommitted` 供视觉/音频/HUD 更新。

- **滞回**（4.4）：静止判定用 `EvaluateEra`（±`anchorHysteresis` 内保持原状态）。
- **快速拖动**：逐阈值检查天然覆盖中间状态，符合检查中间状态的设计方向；测试不等于实机关卡安全验收。

## 6. 状态机（策划 10.6）

```
GamePhase:  Boot → MainMenu → Loading → Playing →（Epilogue → Credits）
PlayingSubState: Free ⇄ AdjustingBoundary / Interacting / Cutscene / Respawning
                 任意 → Paused（记录来源）→ 恢复到来源子状态
```

- `IsPlayerControlAllowed`：仅 `Playing + Free`。`AdjustingBoundary` 锁水平移动与跳跃，重力照常（策划 4.5），**不使用全局 TimeScale=0**。
- `DialoguePlayer` 以 `Story` 及以上优先级播放时自动进入 `Cutscene`，结束回 `Free`。
- 暂停期间对白计时有守卫；物理、语音、协程及拖动释放的完整暂停/恢复仍待修复和验证（见 11）。验收要求暂停停止操作、剧情计时与对白推进，并恢复来源状态。

## 7. 存档与检查点（策划 12.2 / 12.3）

- **数据结构**：`SaveData`（版本号、当前关、检查点、各房间 boundaryX、机关年代状态、已触发剧情 ID、目标、设置）。
- **写入**：`SaveService.SaveProgress` = 序列化 → 写 `progress.tmp.json` → 校验 → 旧正式文件转 `progress.backup.json` → tmp 覆盖正式文件。
- **读取**：正式文件损坏 → 尝试备份（`UsedBackup`）→ 备份也坏 → `Corrupted`（主菜单提示，不静默覆盖唯一记录）。
- **设置独立**：`settings.json` 单独读写；重新开始游戏不重置字幕与音量。
- **恢复顺序**（`GameSession.LoadLevelRoutine` + `CheckpointService.RestoreLatest`）：加载场景 → 恢复边界与年代状态 → 恢复机关 → **放置角色**（优先安全出生点 ID，兜底捕获位置）→ 恢复目标 → 放开输入。先恢复环境再放人，防止夹住。
- **保存时机**：过检查点（`CheckpointService.Capture`）、关键标记写入（`GameSession` 订阅 `FlagAdded`）、离开关卡（`CompleteLevel`）。

## 8. 渲染方案（策划 11.1 / 11.2）

- 背景层：过去/现在两组 Sprite 各配 `SpriteMask`（矩形遮罩，`TemporalVisualController` 按 B 更新左右矩形）；背景 Sprite 用 `Visible Inside Mask`。
- 机关层：`TemporalObject` 子物体（Past/Present）整体启停——渲染与碰撞一致，无"半碰撞"。
- 恒定层：`Mask Interaction = None`。
- 排序层（`ProjectScaffolder` 已配置）：`Sky → FarBuildings → EraBackground → ConstantStructure → EraPlatform → Characters → Foreground → BoundaryFx`。
- 物理层：`Player / Ground / Interactable / Temporal / KillZone / Ladder`（User Layer 8–13）。

## 9. 剧情触发与标记（策划 12.1）

- 触发渠道：`StoryTriggerVolume`（进入区域）、`NarrativeInteractable`（E 调查）、`ExitDoor` 锁定提示（`DialoguePriority.Objective`）。
- 一次性判定：`entry.setFlags` 全部已存在 → 视为已看，跳过（幂等）。
- 优先级（`DialoguePriority`）：`Ambient < Objective < Story < Reveal`。正在播放的句子不被环境触发器截断；当前代码在高优先级打断时调用完成逻辑，低优先级被拒播时也调用完成回调；这是待修差距，不能作为剧情完成契约。应区分完成、玩家合法跳过、拒播/取消；系统打断不得写入未看内容的完成标记。关键片段排队或重试，低优先级片段可舍弃。
- `PhotoRevealed` / `IdentityKnown` 必须绑定照片揭示**整段演出**完成或玩家合法跳过；不能绑定首句或系统打断。跳过仍需完成任务更新与必要镜头收束（策划 12.1）。

### 实现与验收的边界

- 边界当前从 `Update` / 把手回调执行提交；总规划 11.3 要求统一物理步骤提交整组碰撞。后续应将输入目标排队，在统一物理步骤完成验证与提交，再更新视觉、音频和 HUD。
- AABB 代理须覆盖实际目标碰撞；多段树枝与有空洞的形状需要避免大包围盒误阻挡。支撑检测还须确认目标形状确实承接脚下，不能仅检查“目标年代存在某个 Collider”。
- 滞回应覆盖连续拖动、初始状态和存档恢复；`EvaluateEra` 局部有滞回不等于整条提交路径已验收。
- 第 7 节恢复顺序为应达到的契约；冷启动创建玩家、选择正确房间和跨关快照隔离仍见 11 的未闭环问题。剧情阅读进度不随空间快照回滚，目标须与保留的故事标记一致。
