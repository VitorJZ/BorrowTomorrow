# 09 双人分工与模块开发指南

> 本文是两人团队的执行手册：每人认领的模块、每个模块从**当前骨架**到**可交付**的具体开发任务、验收标准与协作红线。
> 文中「A」「B」为分工代号，请在开工前替换为真实姓名并保持全文一致。
> 优先级沿用策划 14 章：P0 = 完整剧情/边界谜题/五关/恢复/字幕/保存/可执行包；P1/P2 依次可裁。

## 1. 分工总览与原则

| 模块 | 负责人 | 分组 |
| --- | --- | --- |
| Core（会话/状态机/接口/数据定义） | **A** | 核心玩法组 |
| Player（输入/运动/攀爬/交互） | **A** | 核心玩法组 |
| TimeBoundary（边界/年代物体/安全/遮罩） | **A** | 核心玩法组 |
| Level（房间/出口/检查点/提示/相机） | **A** | 核心玩法组 |
| EditorTools（脚手架/工具） | **A**（维护） | 核心玩法组 |
| Tests（EditMode 回归） | **A** | 核心玩法组 |
| Narrative（对白/剧情/调查/演出） | **B** | 叙事呈现组 |
| Audio（音乐/音效/环境声） | **B** | 叙事呈现组 |
| Save（存档/检查点服务） | **B** | 叙事呈现组 |
| UI（HUD/把手/面板/菜单） | **B** | 叙事呈现组 |

**为什么这样分**：
- A 的四个模块构成"移动 → 拖边界 → 年代切换 → 安全阻挡 → 抵达出口"的完整玩法循环，内聚在机制层，正是策划阶段 A"机制灰盒"的全部内容；
- B 的四个模块构成"听/看/读/存"的叙事体验闭环（对白、音频、字幕 HUD、进度保存），对应策划阶段 B"一关完整样板"的字幕/音效/存档/构建验收；
- 两人唯一的公共契约是 `Core/Interfaces`——接口先行、各自实现，并行度最高。

**三条总原则**：
1. 跨模块协作只走 Core 接口；**任何接口签名变更必须先在群里知会对方**再提交。
2. 关卡场景内按目录认领（见第 5 节）：空间机关 A 摆，叙事音效 B 挂。
3. 每日收工前 push；发现场景冲突以"登记在先者"为准（05 文档）。
